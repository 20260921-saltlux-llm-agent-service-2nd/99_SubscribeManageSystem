# 📝 Git Commit Convention

## 1. 커밋 메시지 형식

```text
type: 작업 내용
```

- `type`은 소문자로 작성합니다.
- 작업 내용은 간결하고 명확하게 작성합니다.
- 하나의 커밋에는 하나의 논리적 작업을 담습니다.
- 커밋 메시지는 한글로 작성합니다.

## 2. 커밋 타입
- 처음에는 간단하게 하는것을 추천
| Type | 설명 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 코드 리팩토링 (기능 변경 없음) |
| `docs` | 문서 수정 (README 등) |
| `style` | 코드 포맷팅 (공백, 세미콜론 등) |
| `test` | 테스트 코드 추가 및 수정 |
| `chore` | 설정, 빌드 및 기타 작업 |
| `perf` | 성능 개선 |
| `ci` | CI/CD 설정 및 수정 |


## 3. 커밋 메시지 예시

```bash
feat: 회원가입 API 구현
feat: JWT 인증 기능 추가

fix: 로그인 토큰 만료 오류 수정

refactor: 회원 서비스 로직 분리

docs: API 명세서 수정

style: 코드 포맷팅 적용

test: 회원가입 서비스 단위 테스트 추가

chore: GitHub Issue 및 PR 템플릿 추가

ci: GitHub Actions 빌드 자동화 설정
```

## 4. 권장 규칙

- 커밋 메시지만 읽어도 변경 사항을 알 수 있도록 작성합니다.
- 서로 관련 없는 작업은 별도 커밋으로 분리합니다.
- `수정`, `작업 완료`, `업데이트`처럼 모호한 메시지는 피합니다.
- 하나의 PR에는 여러 커밋이 포함되어도 괜찮습니다.
